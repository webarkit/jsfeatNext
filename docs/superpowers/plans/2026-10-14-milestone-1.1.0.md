# Milestone 1.1.0 (GMS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `jsfeatNext.gms` — a bit-exact port of OpenCV's `cv::xfeatures2d::matchGMS` — in `@webarkit/jsfeat-next@1.1.0`, with its prerequisites, the GitHub milestone/project housekeeping, and the release.

**Architecture:** GMS is a new stateless singleton module (`src/gms/gms.ts`, extending `src/core/core.ts`, attached in `src/jsfeatNext.ts`), validated against committed OpenCV fixtures produced by a Python generator run from a gitignored `.venv/`. Its OpenCV/Apache-2.0 provenance is carried by a new licence-header variant, the bundle banner and a licence file shipped in the npm package.

**Tech Stack:** TypeScript 6, Vite 8 library build, Vitest (4 → 5 in Task 7), Node 24 / npm 11, `gh` CLI, Python 3.12 + `opencv-contrib-python` (developer-side only).

**Spec:** [`docs/superpowers/specs/2026-10-14-milestone-1.1.0-design.md`](../specs/2026-10-14-milestone-1.1.0-design.md) — read it before any task; this plan argues from it.

## Global Constraints

- PRs target **`dev`**, never `main`; one branch per issue, created from the latest `origin/dev`; the PR body says `Closes #N`.
- Commits follow Conventional Commits and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; PR bodies end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- Before every commit that touches code: `npm test`, `npm run typecheck`, `node scripts/check-license-headers.mjs` and `node_modules/.bin/prettier --check .` all pass. (Prettier ignores `docs/`, `*.md`, `*.json`, `*.html`, `*.js`.)
- No new `any` (#85). Every `get_buffer` is balanced by a `put_buffer` — enforced for every test by `tests/setup/pool-balance.ts`.
- No new npm dependency. Python never enters `npm ci` or CI. `package-lock.json` is regenerated only with `npx npm@11`.
- New files under `src/`, `tests/`, `examples/` get their header from `node scripts/check-license-headers.mjs --fix`: tests get the *original* variant; `src/gms/**` gets the *OpenCV/Apache-2.0* variant (Task 5) — never the jsfeat one.
- GMS constants: left grid **20 × 20**; right grid sizes per scale index **[20, 10, 14, 28, 40]**; `threshold_factor` default **6**; `with_rotation` / `with_scale` default **false**.
- Agents never push to `main`, never create or push tags, never merge PRs; those are the maintainer's.
- The OpenCV generator runs from `.venv/` in the repository root with the versions pinned in `scripts/requirements-fixtures.txt`; installing `opencv-contrib-python` from PyPI is authorised by the maintainer.

## Review Focus

1. **Keypoints outside the image** (`x ≥ width`, `y ≥ height`, or negative): OpenCV computes a wrong or out-of-range cell; `gms.filter` must never keep such a match and never read out of bounds. Pinned in Task 8 (test + divergence entry).
2. **Match indices past the keypoint arrays** (`queryIdx ≥ keypoints1.length` or `trainIdx ≥ keypoints2.length`): throw a `RangeError` naming the offending match index, never read `undefined`. Pinned in Task 8.
3. **Detector keypoint pools longer than the detected count** (jsfeatNext detectors fill a preallocated `keypoint_t[]` and return a count): only keypoints referenced by matches may be touched. Pinned in Task 8.
4. **State leaking between calls on the singleton** (a scale-path call followed by a default-path call): every call must give the same result as on a fresh instance. Pinned in Task 9.
5. **Duplicate and many-to-one matches** (the same pair twice; several queries → one train, normal for a non-cross-checked brute-force matcher): counted exactly like OpenCV, and the returned array keeps input order and object identity. Pinned in Task 8.

  Rules on top of the upstream logic:
