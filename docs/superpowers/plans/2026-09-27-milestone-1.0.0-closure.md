**Goal:** Close every open issue that defines milestone 1.0.0 (#133, #83, #128, #129) with verifiable evidence, bring the #97 roadmap up to date, fix the two pre-1.0 API traps the audit found in the shipped modules, refresh the docs, and cut the 1.0.0 release.

## Review Focus

Inputs the issues imply but no existing test exercises, most likely to bite first. Each line's test is added to the task that owns the code.

1. **`new pose_estimator(K)` with `fx` or `fy` zero or non-finite** currently yields a NaN pose flagged `good = true` (`invertIntrinsics` divides, `n1 < 1e-12` is false for NaN). Expected: throw naming `fx`/`fy`. Owner: Task 2.
2. **`estimate(H)` with a non-finite entry in `H`** likewise returns NaN with `good = true`. Expected: `good = false`, `R`/`t` untouched. Owner: Task 2.
3. **`estimate(s·H)` for any `s ≠ 0`** must equal `estimate(H)`: a homography is projective, and a caller will pass un-normalised RANSAC output. Owner: Task 2 (pins existing behaviour).
4. **`bfmatcher.match` at 64 bytes under the default `max_distance = 256`** silently drops a pair at distance 300, although at 32 bytes the default accepts every possible distance. Expected: the default accepts any distance the width allows. Owner: Task 1.
5. **A detector pool smaller than the corner count** throws a raw `TypeError` from inside the hot loop, and `fast_corners`/`yape06` leak their scratch buffers on the way out. Expected: a diagnostic `Error` naming the pool size, pool balanced. Owner: Task 5 (#205).

A sixth check is a release step, not a test: the webarkit adapter depends on `"@webarkit/jsfeat-next": "^0.17.0"`, and a caret on a 0.x version excludes 1.0.0. Owner: Task 6.

```ts
describe("pose_estimator degenerate inputs (pre-1.0 audit)", () => {
    const validK = () => jsfeatNext.pose_estimator.intrinsics(640, 480);

    it("rejects intrinsics with a zero or non-finite focal length instead of producing a NaN pose", () => {
        const K0 = validK();
        K0.data[0] = 0;
        expect(() => new jsfeatNext.pose_estimator(K0)).toThrow(/fx=0/);
        const est = new jsfeatNext.pose_estimator(validK());
        const Kn = validK();
        Kn.data[4] = NaN;
        expect(() => est.setIntrinsics(Kn)).toThrow(/fy=NaN/);
    });

    it("a homography with a non-finite entry yields good=false, never a NaN pose flagged good", () => {
        const est = new jsfeatNext.pose_estimator(validK());
        for (let i = 0; i < 9; ++i) {
            // every entry, so the translation column (indices 2, 5, 8) is covered too
            const H = synthH(validK(), rodrigues(0, 1, 0, 0.3), [0.1, -0.2, 2.0]);
            H.data[i] = NaN;
            const pose = est.estimate(H);
            expect(pose.good).toBe(false);
            expect(Array.from(pose.R.data).every(Number.isFinite)).toBe(true);
            expect(Array.from(pose.t).every(Number.isFinite)).toBe(true);
        }
    });

    it("is invariant to the homography's projective scale: estimate(s*H) equals estimate(H)", () => {
        const K = validK();
        const est = new jsfeatNext.pose_estimator(K);
        const H = synthH(K, rodrigues(1, 2, 0, 0.7), [0.3, 0.1, 3.0]);
        const Hs = new jsfeatNext.matrix_t(3, 3, F64C1);
        for (let i = 0; i < 9; ++i) Hs.data[i] = -2.5 * H.data[i];
        const a = est.estimate(H);
        const b = est.estimate(Hs);
        expect(a.good && b.good).toBe(true);
        for (let i = 0; i < 9; ++i) expect(b.R.data[i]).toBeCloseTo(a.R.data[i], 9);
        for (let i = 0; i < 3; ++i) expect(b.t[i]).toBeCloseTo(a.t[i], 9);
    });
});
```

### Task 5 (optional, recommended): #205 — detector pool overflow guard

Not in the milestone. Option 1 (silent truncation) is rejected on the issue's own reasoning; option 3 leaves the buffer leak in place.

**Files:**

- Produces: unchanged signatures; `detect` throws `Error("jsfeatNext.<module>.detect: corners pool of N is full; the image yields more corners, pre-allocate a larger pool")` when `count === pool.length` and another corner is found.
