# FREAK descriptor (#80) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `jsfeatNext.freak`, a FREAK descriptor bit-exact with OpenCV 4.10.0: descriptors, kept keypoints and angles. It drops border keypoints by compacting `corners` and returning the kept count, and it never builds OpenCV's 8.5 MB pattern table.

**Architecture:** A port of `FREAK_Impl` (opencv_contrib `freak.cpp`): `buildPattern`, `computeDescriptors<uchar, int>`, `meanIntensity`, and the generic `extractDescriptor`. Pattern points are computed on demand from `buildPattern`'s expressions. Only the 512 default pairs and the 45 orientation pairs are module-level tables. Per-parameter constants are computed per call: `patternSizes`, the orientation weights and `sizeCst`. It runs over a shared-pool integral image and emulates OpenCV's float32 arithmetic with `Math.fround`. The module is a tree-shakeable singleton, wired like `teblid`. Ground truth comes from fixtures made with the pinned wheel, on this machine (TEBLID's T5, here F4).

**Tech Stack:** TypeScript, Vitest, Vite, the Python fixture generator (`opencv-contrib-python==4.10.0.84`).

**Spec:** [`docs/superpowers/specs/2026-10-30-freak-design.md`](../specs/2026-10-30-freak-design.md). Read it first. Section numbers below (§N) and decisions (F1–F6) refer to it. The TEBLID module (`src/teblid/`) and its plan, [`2026-10-29-teblid.md`](2026-10-29-teblid.md), are the precedent for every pattern not spelled out here.

## Global Constraints

- **PR and commits:**
  - The PR goes against `dev`, from branch `feat/80-freak`.
  - Commits are Conventional Commits with `Refs #80`; the PR says `Closes #80`.
  - Commits are GPG-signed; never bypass signing.
- **Checks:** `npm test`, `npm run typecheck`, `node_modules/.bin/prettier --check .`, `node scripts/check-license-headers.mjs` and `npm run build-ts` are green before every commit that touches code.
- **OpenCV version:**
  - OpenCV 4.10.0 only.
  - Citations are pinned: `https://github.com/opencv/opencv_contrib/blob/4.10.0/modules/xfeatures2d/src/freak.cpp#L<a>-L<b>`.
- **Fixtures:** generated only with `.venv/Scripts/python -I scripts/gen-opencv-fixtures.py`, on this Windows x86-64 machine (F4).
- **Code rules:**
  - No new `any`.
  - Every `cache.get_buffer` is returned in a `finally`.
  - Every module-level `new` gets the pure annotation (AGENTS.md). Never write the literal annotation keyword in a comment: rolldown misreads it.
- **Headers:**
  - New files under `src/freak/` carry the new **opencv-freak** variant (BSD-3-Clause, F6).
  - New tests, bench and example carry the **original** variant.
- **Bit-exact means equal on every output:** every byte, the kept indices, and the angles.
  - No tolerance, and no dropping fixture inputs.
  - A mismatch traced to `cos`/`sin`/`pow`/`logf`/`atan2f` at a float32 boundary is reported to the maintainer with the case, not worked around (§5, "Known risks").
- **Pool sizing:** the pattern lives in no buffer larger than a few KB (F1). The PR states the module's resident memory.

## Review Focus

1. **Images of 2²³ pixels or more** (e.g. 4096×2048). OpenCV switches to a `double` integral there, and an `Int32` integral would overflow. Expected: no overflow, correct means → Task 3, a property test on an all-255 4096×2048 image, where every comparison `v[i] >= v[j]` holds, so every byte is `0xFF`.
2. **Two calls with different options, back to back** (`pattern_scale: 8`, then the defaults). A stale per-parameter cache would leak between calls. Expected: the second call equals a fresh call with the defaults → Task 3.
3. **A keypoint exactly on the drop threshold** (`x === patternSizes[s]`, or `x === cols − patternSizes[s]`). The comparison is `<=` / `>=`, so it is dropped → fixture cases in Task 1.
4. **Duplicate keypoints** (the same `x`, `y` and `size` twice). Both are kept, with identical rows and angles. The generator cannot match duplicates uniquely, so the fixture avoids them → a property test in Task 3.
5. **`count < corners.length`.** Only `corners[0..count)` is compacted; `corners[count..]` keeps the same objects in the same slots → Task 3.

### Task 1: FREAK fixtures

**Files:**
- Modify: `scripts/gen-opencv-fixtures.py` (a new `freak` group in `GENERATORS`, `--only freak`), `tests/fixtures/opencv/README.md`
- Create: `tests/fixtures/opencv/freak.json`

**Interfaces:**
- Produces `payload.cases`, an array of objects with these fields:
  - `name: string`;
  - `image: "scene" | "scene_rot90" | "flat"`;
  - `options: { orientation_normalized: boolean, scale_normalized: boolean, pattern_scale: number, n_octaves: number }`;
  - `keypoints: [x, y, size][]`, the input;
  - `kept: number[]`, the input indices in OpenCV's output order;
  - `angles_deg: number[]`, float32 values, one per kept keypoint;
  - `descriptors: string[]`, 128 lowercase hex characters per kept keypoint.
- Also produces `payload.rotation = { case_a, case_b, pairs: [ia, ib][], max_hamming: number }`. The pairs are corresponding kept keypoints in the `scene` default case and in the `scene_rot90` default case; `max_hamming` is OpenCV's largest Hamming distance between their descriptors.
- Values are float32-representable, written as `numpy.float32(v).item()`.
- `scene_rot90` is `numpy.rot90(scene)` (counter-clockwise, 480 × 640). A keypoint `(x, y)` maps to `(y, W − 1 − x)`, with `W = 640`. Its sha256 goes in `meta.params`.
- `meta.algorithm = "freak"`; `meta.params.opencv_call = "cv2.xfeatures2d.FREAK_create(orientationNormalized, scaleNormalized, patternScale, nOctaves).compute(image, keypoints)"`.

  - a `flat` case: a 96×96 image of constant value 100, with three interior keypoints, so `atan2(0, 0)` is pinned by OpenCV;

### Task 3: the FREAK engine

**Files:**
- Create: `src/freak/freak.ts`, `tests/parity/freak.test.ts`, `tests/properties/freak.test.ts`

**Interfaces:**
- Consumes:
  - the Task 2 tables;
  - `keypoint_t.size`;
  - `imgproc.compute_integral_image`, or a local integral, as long as the sums stay exact for images of 2²³ pixels or more (Review Focus 1).
- Produces `export class freak extends jsfeatNext` (the `core` base), with `describe(src: matrix_t, corners: keypoint_t[], count: number, descriptors: matrix_t, options?: FreakOptions): number`.
- Produces `export interface FreakOptions { orientation_normalized?: boolean; scale_normalized?: boolean; pattern_scale?: number; n_octaves?: number }`. The defaults are `true`, `true`, `22`, `4`.

- [ ] **Step 1: Write the failing parity test** `freak.test.ts`. For every case:
  - build `new keypoint_t(x, y, 0, 0, -1, size)` per input, in a fresh array, keeping the original objects;
  - `const kept = freak.describe(img, kps, kps.length, d, options)`;
  - assert `kept === kept_fixture.length`;
  - assert `kps[i] === originals[kept_fixture[i]]` (same object);
  - assert `kps[i].angle === Math.fround(angles_deg[i]) * 0.017453292519943295`;
  - assert the hex of row `i` equals the fixture.

  Each failure names the case and the index.
- [ ] **Step 2: Write the failing property tests** `tests/properties/freak.test.ts`:
  - with `scale_normalized`, a `size` of `0` or `-3` at index 2 throws a `RangeError` whose message contains `"2"`; with `scale_normalized: false`, the same keypoints do not throw;
  - non-finite `x` at index 1 throws, naming `"1"`;
  - `pattern_scale` of `0`, `-1`, `NaN` or `1e39` throws, and so do `n_octaves` of `0`, `2.5` and `-1`;
  - `count > corners.length` throws, with the pool size unchanged;
  - a non-`U8C1` source throws a `TypeError`;
  - `count = 0`, and keypoints that are all at the border, return `0` with 0 rows;
  - the input `angle` has no effect: the same bits for `-1`, `0` and `2`;
  - with `orientation_normalized: false`, every kept angle is `0`;
  - **rotation:** for the fixture's `rotation.pairs`, our `scene` and `scene_rot90` descriptors have a Hamming distance `<= rotation.max_hamming`, and the angles differ by 90° ± one orientation step (`360/256`), modulo 360;
  - Review Focus 1: an all-255 4096×2048 image with an interior keypoint (size 20) gives 64 bytes of `0xFF`;
  - Review Focus 2: `pattern_scale: 8`, then the defaults, equals a fresh default call;
  - Review Focus 4: duplicate keypoints are both kept, with identical rows and angles;
  - Review Focus 5: `corners[count..]` holds the same objects afterwards;
  - a flat 64×64 image of value 100 with an interior keypoint gives angle `0` (`atan2(0, 0)`) and all bytes `0xFF`;
  - a throw mid-way leaves the shared pool balanced;
  - unit `cvRound`, half to even: `0.5 → 0`, `1.5 → 2`, `-0.5 → 0`, `2.5 → 2`.

  - `descriptors.resize(64, kept, 1)`. Return `kept`.
